# 并发 CDN 加载 V2：配置、多源与中国大陆候选优先

V2 将初版的固定 4 路、256 KiB、单一 CDN 传输改为可配置的多 CDN 分块下载。设置默认仍然关闭。本文描述 V2 的最终设计；[V1 记录](parallel-cdn-playback.md)作为历史验证资料保留，其中的固定参数、单 CDN 和旧安装包信息不适用于 V2。

海外 CDN 未缓存某些视频是本次改进考虑的一种可能原因，目前没有对用户卡顿的视频取得缓存命中、回源或链路证据，不能据此确认具体故障原因。V2 的目标是增加中国大陆候选来源和并发能力；是否改善实际播放，需要同视频、同画质的现场对比。

## 使用方式及变化

在“设置 → 音视频设置 → 并发 CDN 加载（实验性）”开启，重新打开视频或切换播放源。修改参数也在下一次加载播放源时生效。

| 设置 | V2 默认值 | 可选范围与行为 |
| --- | --- | --- |
| 并发 CDN 加载 | 关闭 | 针对本地 DASH 点播；开启后视频、音轨共用同一下载器额度 |
| 并发路数 | 8 路 | 1–32 的整数；提供常用值及自定义输入 |
| 分块大小 | 1024 KiB，即 1 MiB | 64–4096 KiB 的整数；提供常用值及自定义输入 |
| CDN 选择 | 中国大陆候选组优先 | 组内轮转，不按测速、响应时延或完成先后排名 |

参数保存在现有设置存储中。自定义输入必须为范围内整数；导入的超范围整数会限幅，非法类型会采用默认值。并发数表示共享的最大在途上游请求数，包含探测和内容校验；它不是保证一直存在的下载连接数，也不等于 CDN 节点数量。

开启后，原来的“CDN 设置”“CDN 测速”“音频不跟随 CDN 设置”立即不可编辑，播放器菜单中的手动 CDN 入口也会停用。已经打开的 CDN 选择框会移除选择项并取消正在进行的测速。旧设置会保留；关闭并重新加载播放源后恢复原选择。即使启用应用代理导致并发功能跳过，手动 CDN 仍按开关状态停用，播放改用接口原始地址。

## 候选来源与地区规则

每个 DASH representation（特定画质、编码或音轨）分别保留接口返回的 `baseUrl` 与 `backupUrl`。只收集相同媒体路径的有限候选，最多保留 4 个原始地址；不同画质、不同音轨、不同路径不会混成同一资源。切换画质或音质会重新建立播放源和资源会话。

中国大陆候选域名沿用 [Bilibili-thread-ripper 的 `MAINLAND_HOSTS`](https://github.com/MrTangLuyao/Bilibili-thread-ripper/blob/ee8709161e5a04cce2260a2937835e37f91ebcfb/src/cdn-resolver.js#L6-L15)，取证提交为 `ee8709161e5a04cce2260a2937835e37f91ebcfb`：

```text
upos-sz-mirrorali.bilivideo.com
upos-sz-mirrorhw.bilivideo.com
upos-sz-mirrorbos.bilivideo.com
upos-sz-mirror08c.bilivideo.com
upos-sz-mirrorbd.bilivideo.com
upos-sz-mirror14b.bilivideo.com
upos-sz-estgoss.bilivideo.com
upos-sz-mirrorcos.bilivideo.com
```

这是上游项目对服务域名的地区归类，不是实时 IP 地理定位。DNS、调度及服务商路由可能变化；域名归类不能保证实际物理节点始终在中国大陆，也不能证明某个节点已缓存当前视频。

仅对受支持域名下的普通 `/upgcxcode/`、`.m4s` / `.mp4` 媒体地址生成镜像候选；保留路径、签名查询参数和必要媒体请求头。不会将 peer CDN 的 `/vN/resource` 等路径硬改成普通镜像地址，也不允许播放器通过本地代理提交任意 URL。

调度顺序如下：

1. 先考虑中国大陆候选组。准备阶段只提前探测一个并发窗口的候选，并按固定顺序读取结果；有效候选的内容校验先于更多候选探测，避免无用节点的超时阻塞起播。响应最快者不会因此获得优先权。
2. 通过内容校验后，在该组内按固定节点次序轮转分块，每轮先使用不同域名，再考虑各域名的其他签名候选。可用性或字节校验失败的候选在当前请求中被跳过。
3. 当前块的大陆候选不可用后，才尝试接口提供的未知地区或海外原始候选；没有额外合成海外节点池。
4. 大陆候选的 HTTP 重定向也受地区限制，不能靠重定向静默进入未知或海外组。

因此，V2 不继承原插件基于测得吞吐的排名、自适应分配或独立插件更新机制。它仍是 PiliPlus 内置的 Dart 下载器，随客户端更新。

## 内容一致性和失败处理

```text
接口返回同一 representation 的主、备用地址
    ↓ 保留每个地址的路径和签名
中国大陆候选组 → 不可用时再尝试接口原始候选
    ↓ 总长、首部及中部样本校验
多个 CDN 分担 Range 分块 → 有界窗口 → 按字节顺序回传
    ↓
现有 media_kit / mpv 播放器
```

首个有效候选提供参考总长度，并读取开头和中部各最多 4 KiB 样本。另一候选加入前，必须总长一致且两个样本逐字节一致。相同长度和开头一致而中部不同的地址会被拒绝。样本检查不能替代整文件加密摘要；签名镜像资源及分块协议校验仍是该实现的信任边界。

每个分块必须为 `206`，`Content-Range` 起止与请求一致，总长稳定，正文长度准确。`ETag` / `Last-Modified` 只在同一候选内部用于检测资源变化；不同服务商对同一文件可能返回不同 ETag，不能将跨 CDN 的 ETag 不同直接判为内容不一致。组合输出不冒充具有某一个上游的 ETag。

某块失败时，先在大陆组内重试其他可用候选，再按上述规则回退。准备或首块失败且尚未输出媒体正文时，可保留原始方法和 Range 改为单流透传原始地址。已经输出正文后如果所有候选均失败，只能截断当前响应，不能追加另一份完整响应；播放器可能自行重试，也可能需要用户手动重载。

代理仅监听随机 loopback 端口，使用随机资源令牌，限制可注册资源和活动请求数。关闭播放、seek 断开和切换来源会取消无用请求、释放连接及预取块；不会把完整签名 URL 写进常规日志。

本地并发代理启用时，通过当前媒体的 `loadfile` 选项将播放器网络等待上限设为 60 秒，以容纳地区切换和内容校验；普通直连播放继续使用播放器原有默认值。此项是等待上限，不是起播目标，也不改变每次上游请求的 10 秒超时。

## 并发与内存边界

同一播放会话的音视频共用并发限制；每条音轨不会额外获得一份完整额度。预取采用滑动窗口：前面的块按序送出后即可补充新工作，无须等待整批全部完成。顺序输出仍可能受最前面慢块影响。

预取 payload 的共享预约上限为 **64 MiB**，单个下游请求的预取窗口最多占 **32 MiB**。为避免播放器必须同时取得音视频起始数据、却被另一轨预取占满额度导致等待，每个活动请求的首块不占用这份预取预算，最多另占 **4 MiB**；活动请求最多 8 个。

64 MiB 是预取字节预算，不是应用总内存上限。首块、内容校验样本、暂时的字节复制、网络/TLS 缓冲和播放器自身缓存均另计。大块配置、内存预约、候选探测及顺序输出都可能使实际并行度低于设置值；32 路加 4096 KiB 不意味着持续同时预取 128 MiB。增加路数或块大小也不保证更快，并可能增加额外请求、内存和未播放流量。

## 适用范围与已知限制

| 场景 | V2 行为 |
| --- | --- |
| DASH 视频及其音轨 | 使用多 CDN 分块；视频页“仅播放音频”也通过同一下载层 |
| 独立音频页面 | 开关开启时绕过旧手动 CDN，使用原始来源；此页面没有新增并发代理 |
| 应用自定义代理开启 | 不启动本地并发代理，使用原始来源；手动 CDN 设置仍停用 |
| 直播、离线下载、投屏、非受支持媒体路径 | 不纳入本次多 CDN 下载范围 |
| 本地代理不可用或资源无法注册 | 保留直接播放路径 |
| CDN 签名拒绝、地区服务变化、部分节点无内容 | 可用性与校验失败触发候选回退；不绕过内容访问权限 |

更多 CDN 可能引入更多准备请求或超时等待；严格地区优先本身也可能比速度竞选慢。局部样本通过不等于所有视频或所有时段均兼容。当前没有持续播放的对照证据能证明 V2 对用户网络一定提速，也没有证据确认此前卡顿的根因是海外 CDN 缓存未命中。
