提案日期：2026-09-27（Asia/Singapore）。来源：用户要求由代理自行运行视频测试，并先提供下一版直播整合的编译内容供 review。用户已批准实施，并明确要求本版包含完整送礼、入团和灯牌流程。自 2026-09-28 起进入实现；新包和在线交易的验证状态分别记录。

## 版本与交付目标

基线为 `e3e31dc87ca3260c1fbd1b3fbd86a797ec352f3e`：官方 PiliPlus 2.1.5、已有 CDN P0、自动化测试工具。2026-09-27 通过官方仓库 release 查询核对，最新正式版仍为 [2.1.5](https://github.com/bggRGjQaUbCoE/PiliPlus/releases/tag/2.1.5)，不将定制版本称为官方新版。

建议显示版本为 **`2.1.5-CDN-P0-LIVE-L2+<实际递增构建号>`**，保留 CDN P0 标识。首轮目标平台为 macOS，产物为 universal Release 的 `.app` 与 `.dmg`，附版本、提交、架构、最低系统、SHA-256、签名和验证记录。构建号在最终提交确定后生成，不提前编造。

本版目标是默认关闭的直播增强界面、直播消息正确性与恢复，以及原生礼物发送、背包、入团、勋章管理和灯牌流程。用户选择的范围覆盖 L1 与 L2；实现、确定性验证和真实账号交易验收分别记录。完整网页/PC 功能对齐仍是总目标，必须逐模块达到验收；本次不会把未接入的按钮或官网跳转算作等量完成。

## 互动能力的接入门槛

礼物、粉丝团与灯牌是本次目标的一部分，不能从 BTR 插件取得。依据为[官方模块清单](research/04-official-live-module-inventory.md)，历史 13 份资源、42 条观察和 21 条端点线索仍不是已验证合约。读取模块进入本版前，需要重新从当前官方页面取得资源并核实公开请求；账号私有读取另外记录登录条件，不从测试脚本读取用户凭据。

本轮新增匿名只读复核：官方房间 6 的 [礼物目录 GET](https://api.live.bilibili.com/xlive/web-room/v1/giftPanel/roomGiftList?room_id=6&platform=pc) 返回 HTTP 200 / API 0，包含 `gift_data`、`gift_config`、`global_config`，其中当前 gold_list 有 58 条；粉丝团 H5 和其入口脚本可读取，摘要与历史资源一致。这个单房间匿名响应支持继续实现目录读取，但价格单位、登录背包、房间差异、权限、写操作和 H5 回调仍未形成完整合约。新证据见 [2026-09-27 只读复核](research/official-live-readonly-probe-2026-09-27.json)，历史 manifest 不改写。

## 测试与编译顺序

1. **只读合约复核**：记录当前官方资源 URL、摘要、日期及每个读取接口的方法、参数、权限、字段和错误；静态字面量不升级为已验证接口。无法核验的模块作为明确未落地项报告。
2. **实现和确定性测试**：设置缺失/非法/恢复；SC 重复、乱序、删除先于快照、隐藏后到期、常驻模式；断线/鉴权失败/无服务器/关闭后的退避；旧房间 HTTP 和消息不得污染新状态。
3. **生命周期与界面**：播放中至少 20 次增强开关切换，播放器实例、拉流次数、音量、清晰度不变；无重复订阅。宽/窄窗口、全屏、画中画、仅音频、字号缩放和输入焦点均验证。
4. **原有回归**：保留 42 Dart + 11 Flutter 用例的真实计数，并运行工具检查；框架生命周期事件不当成用例。新测试数量在实际运行后记录，不提前写“通过”。
5. **macOS Release**：核对显示版本与 native bundle 版本、arm64/x86_64 架构、实际最低系统、回环权限、签名结构与 DMG 摘要。旧包最低系统实测 12.0，源配置中的 10.14/11.0 不能作为新包支持声明。沿用本地 ad-hoc 签名，未做 Apple 公证。
6. **GUI / 在线验收**：普通游客房间先行，记录真实打开、开关、布局、聊天/榜单、断连恢复和 SC 观察；未出现的真实事件不能只凭夹具标在线通过。新装设置使用独立测试存储或隔离容器，不读取/清空用户现有账号或偏好。
7. **交付**：按实际通过内容打包，附完整未落地清单；账号修改/付费流程、官方 PC、其他平台未验收则保持原状态。
