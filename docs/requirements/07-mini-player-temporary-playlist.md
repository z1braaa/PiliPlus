# 应用内小窗与临时播放列表需求

提出日期：2026-09-28。本文记录新增需求及验收口径，**尚未实现或运行验收**。现有 PiliPlus 的桌面/系统画中画、后台画中画和哔哩哔哩账号“稍后再看”是不同能力；不能凭现有入口把下列项目标为完成。状态统一以[追踪表](../harness/traceability.md)为准。

## 应用内小窗播放（`MINI-01`～`MINI-05`）

在设置中提供独立开关，默认关闭以保留现有返回行为。这里的“播放视频到一半”指**视频尚在播放时离开详情页**，不设播放进度达到 50% 的门槛，也不在时间轴到一半时自动弹出。开启后，点播详情页或直播观看页被用户返回/切换至应用其他页面时，当前播放会话转入应用窗口内的小窗；在应用内继续导航不停止播放。小窗不是浮在其他应用上方的系统 PiP，也不是新建一条流。

| ID | 行为与最小验收 |
| --- | --- |
| MINI-01 | 开关开启且点播播放中离开详情页、或直播播放中离开房间页，小窗只出现一次并继续同一会话；开关关闭维持原返回行为。点播未起播、已自然结束及直播未开流，不凭页面离开创建空白小窗。 |
| MINI-02 | 小窗位于 PiliPlus 应用内，可移动并拖动调整尺寸；视频保持正确比例，不遮住关闭/还原操作；窗口缩放、窄窗、全屏退出与平台安全区域下不会失去操作入口。小窗不会以系统级悬浮覆盖其他应用。 |
| MINI-03 | 在应用内连续切换页面，小窗持续播放；进入对应播放页可还原主播放器，保留进度或直播会话、暂停状态、音量、清晰度和当前线路，不额外重建播放器或重复拉流。 |
| MINI-04 | 明确的关闭按钮停止当前播放并销毁小窗；普通导航、仅关闭其他弹窗或小窗失焦不停止。视频自然播毕、直播源失效和应用退出按已有播放结束/错误规则处理，不声称会无期限持续。 |
| MINI-05 | 与已有桌面/系统 PiP、后台播放和全屏互斥管理：任一时刻只有一个活动画面/声音会话；切换模式、切账号/房间、打开另一媒体时不会出现双音频或旧画面，旧会话按可见结果释放。 |

**验收样本**：点播播放中返回首页并跨至少三个应用页面，拖动/缩放、暂停/继续、还原、再离开及手动关闭；直播播放中返回并重复同组动作；关闭开关作对照；另测自然结束、直播断流、系统 PiP 切换和新媒体取代。记录播放器实例/拉流数与用户可见进度、画面和声音。macOS、Windows/Linux 与移动端分别记录实测或未运行，不能以 macOS 结果外推。

## 临时播放列表（`TEMP-01`～`TEMP-08`）

独立设置默认**开启**。临时列表是 PiliPlus 的应用内播放队列，区别于哔哩哔哩账号的“稍后再看”、收藏夹，以及视频本身的分 P/合集列表。单条操作从视频卡片旁的三个点“更多”菜单进入；批量操作从所在播放列表/收藏列表的更多菜单进入。操作不会立刻跳走或打断当前视频。

| ID | 行为与最小验收 |
| --- | --- |
| TEMP-01 | 新装、旧配置缺失和重置默认均开启临时列表入口；用户关闭后不出现添加入口/自动接管连播，再开启时按确定的保存策略恢复。该设置不改点播 CDN、直播增强或账号“稍后再看”。 |
| TEMP-02 | 视频卡片更多菜单有“添加至临时播放列表”。当前有播放项时，加入该项之后、其余待播项之前，成为**下一条**；无当前播放项时加入队列尾。菜单完成后显示实际队列位置和数量，当前播放不中断。 |
| TEMP-03 | 同一菜单有“添加至临时播放列表并最后播放”。该项追加在所有待播项之后；当前视频和既有待播顺序不变。前一动作与本动作面对同一队列时产出不同且可检查的位置。 |
| TEMP-04 | 临时列表每条视频右侧显示三横线拖动把手；长按/拖动改变顺序，松手后列表及后续播放顺序一致。播放中的条目不可因拖拽而重启；键盘/无障碍操作应有等价排序入口。 |
| TEMP-05 | 播放列表与收藏列表各自的更多菜单有“全部添加至临时播放列表”。按当前列表可见排序遍历**全部分页**，保持其相对顺序地追加到待播尾部；显示数量、进度、跳过的失效项与部分失败，支持取消后保留已完成项，不将只加载的第一页冒充全部。 |
| TEMP-06 | 临时列表更多菜单有“全部添加至收藏”。登录后可选择已有收藏夹，或先新建收藏夹再添加；确认页列出目标、数量及可能重复项。服务端确认每个加入/已存在结果，未登录提示登录且不发写请求；部分成功、失败/超时和重复点击分别提示与核对，未知结果不盲目整批重发。 |
| TEMP-07 | 从播放器或应用导航可到达临时列表；列表提供明确的当前项、待播顺序与播放入口。一项自然播毕后按排序进入下一项，用户选另一项时不能同时保留旧音频。失效/无权限视频有可见状态，不在无提示时无限循环重试。 |
| TEMP-08 | 队列与“稍后再看”/云端收藏的数据写入分离；仅 `TEMP-06` 经用户确认后写收藏。切账号、退出登录及应用重启时的队列保存/清除策略需在实施前确定，并以同一策略覆盖升级和恢复测试。 |

**位置示例**：当前播放 A，待播为 B、C。对 D 选择“添加至临时播放列表”后顺序为 A、D、B、C；在同样初始状态下选择“添加至临时播放列表并最后播放”后为 A、B、C、D。“全部添加”以当前列表的展示顺序追加，例如 E、F 得到 A、B、C、E、F。拖动把手调整后，自然连播遵从拖动后的顺序。

**收藏批量验收**：游客点击应只展示登录要求；已登录分别试已有收藏夹与新建收藏夹，核对账号端最终收藏状态、重复项和部分失败。涉及收藏写操作，不以本地按钮变色或 HTTP 请求发出即宣称完成。

## 实施前仍需定的细节

- 临时列表的生命周期：只保留当前应用会话，还是跨重启保留；退出登录或切账号后是否隔离队列。`TEMP-08` 未确定前不能将持久化行为标为已验证。
- 同一视频、不同分 P 或合集条目的去重键；再次单条/批量添加已有项时是移动位置还是保留副本。界面应反馈实际结果，并保证批量操作不会因重复点击产生不可解释的重复项。
- 可批量添加的“播放列表”具体包括视频详情内分 P/合集、账号稍后再看与公开列表的哪些入口；账号权限与分页数量上限按各来源核对，不能静默只处理第一页。
- 小窗遇到打开另一个媒体、进入系统 PiP、应用后台、直播自动跳房间时的优先级；`MINI-05` 的单会话约束是已定底线，具体切换动画与是否保留待播队列在实现设计时细化。

这些是实现选择，不影响已明确的开关默认、插入位置、拖动排序、批量入口和服务端收藏核对要求。每项完成后按[验收记录](../harness/validation.md)分别标明源码、自动检查、GUI 与账号端验证结果。
