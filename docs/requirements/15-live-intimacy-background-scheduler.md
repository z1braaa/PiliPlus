## 1. 目标与范围

将当前“实际播放房间的亲密度自动任务”扩展为应用级后台任务队列。用户无需打开任务房间，队列即可在已授权的直播间之间依次推进任务；用户的前台观看行为与后台任务执行分开。

本功能仅自动处理**点赞、弹幕、观看时长**三项亲密度任务，不自动送礼、赠送粉丝团灯牌、入团、购买、续订或执行其他消费操作。已有勋章不代表允许自动执行这些操作。

播放器继续采用 Flutter / media_kit / mpv。后台任务使用独立、静音的**“仅播放音频”**会话，不使用浏览器、Electron 或前台播放器模拟任务。不影响点播并发 CDN、手选 CDN 和直播画质设置。

## 2. 已明确对齐的行为

| 事项 | 用户选择／需求 |
| --- | --- |
| 未授权的前台房间 | 打开房间不自动授权；仍须满足资格并手动开启该房间开关 |
| 弹幕内容 | 每个房间独立保存文字或该主播的1～5个候选表情；表情模式每次随机选一个，不跨房套用表情 |
| 观时展示 | 实时展示有效观时及当前轮进度；区分本地估算与服务端已确认轮数，不将未结算时间标为已获得亲密度 |
| 后台播放方式 | 独立播放器、静音、开启现有“仅播放音频”模式 |
| 运行范围 | 应用仍运行时继续，包括最小化、离开或暂停前台直播；真正退出应用、系统休眠时停止 |
| 匿名观看／暂停记录观看 | 暂停整个后台亲密度队列，提示冲突，由用户自行调整；不自动修改设置 |
| 音频失败 | 暂停该房间并提示，继续其他房间；不回退到视频 |

## 3. 控制、授权和配置

### 3.1 应用总开关

在“设置 → 其他设置”增加“后台亲密度任务”入口，提供：

- 总开关，首次默认关闭，只能由用户手动开启。
- 执行顺序：勋章等级高→低／低→高。
- 当前任务房间、三项任务进度、观时计时／进度条、排队房间和暂停原因。
- 已授权房间列表，以及停用／删除授权的操作。

总开关、排序和房间配置按登录账号隔离并保存。关闭总开关停止后续自动操作，释放后台播放器，但保留用户配置；重新开启或重启应用后，先重新核对资格、任务和未决操作，再恢复用户已保存的选择。

总开关与现有“直播界面增强”显示开关独立。关闭增强界面不能意外停止或启动已授权队列，房间授权和内容配置应有可达的入口。

### 3.2 房间开关与前置检查

每个直播间的亲密度区域增加“此房间自动亲密度”开关，首次默认关闭。首次授权必须由用户在该直播间明确操作，不能因进入房间、关注主播、获得勋章或开启总开关而自动授权。

开启前必须检查：

1. 自动点赞已开启。
2. 自动弹幕已开启。
3. 该房间当前选择的发送模式已设置有效内容：文字模式要求非空文字；表情模式要求已选择该主播1～5个不同表情，且其中至少一个当前可发送。另一模式中已保存的内容不能代替此项检查。

条件不足时，不开启房间授权；指出缺少哪一项，并提供配置入口。此时总开关可以保持关闭，允许用户先配置、授权房间。

关闭任一互动开关、清空当前模式的内容，或表情模式下候选全部不可用／权限无法确认后，暂停该房间并显示原因，不静默重新开启开关或替换发送内容。文字模式不因未使用的表情池失效而暂停。部分候选失效时，按下一节的规则仅在剩余有效候选中发送。保留原授权选择，待用户修正后重新核对资格与服务端状态。

### 3.3 内容与迁移

配置以**账号 + 主播身份 + 真实房间**绑定，处理短房间号和真实房间号的对应关系，避免同一房间重复排队。

文字、候选表情列表和当前发送模式逐房间保存，自动发送不占用、清空或改写手动弹幕草稿。文字模式与表情模式分别配置，不能在未选择的模式之间自动回退。

表情模式规则：

- 从该房间官方可发送列表中选择1～5个不同表情，显示已选数量，例如“3/5”；按表情唯一标识去重，第6个不能加入。选择0个时不能启用表情自动发送。
- 每个候选都绑定当前账号、主播和真实房间，保存完整候选列表；重启后保留选择，不跨主播套用。
- 每次到达发送时机，重新核对候选所属房间和权限，在用户已选且当前可发送的候选中等概率随机选一个；每次只发一个。独立随机允许连续两次选中相同表情，只有1个候选时沿用单表情行为。
- 部分候选明确失效时，标记不可用并仅从其余有效候选中选择，不自动删除用户配置。全部失效或权限查询结果不可靠时，暂停并提示，不从候选池外选择表情，也不发送备用文字。
- 表情选择随机与30～60秒发送间隔随机分别执行；候选数增加不增加每次发送条数或任务预算。提交结果未知时，先核对，不重新随机选择并盲目补发。

现有账号级自动点赞／弹幕偏好只能用于配置参考，不能自动创建后台授权。更新后，旧前台自动任务不能绕过总开关和房间开关；统一调度器与原前台自动任务必须互斥，防止重复发送。

## 4. 房间资格与发现

一个房间可以进入待执行队列，必须同时满足：

- 当前账号已登录且身份稳定，总开关开启。
- 用户已关注该主播，并拥有该主播的粉丝勋章。
- 主播正在直播。
- 用户已经对该房间单独授权。
- 自动点赞、自动弹幕和发送内容配置有效。
- 尚未被服务端确认当日三项任务全部完成。

发现房间时完整处理关注直播列表和勋章列表的分页，按主播身份求交集，规范化真实房间号。缓存可用于展示，执行前仍需重新核对开播、权限和任务状态。查询失败不等于取消关注、勋章失效或任务完成。

检测到或服务端确认取消关注、失去勋章、下播后，立即停止该房间的待发操作并移出可执行队列；用户在本地撤销授权时立即取消，无需等待下次扫描。无需自动打开房间页面，也不自动佩戴勋章或执行付费点亮操作。

## 5. 串行调度与前台优先

### 5.1 调度顺序

同一账号同一时刻最多有一个自动任务目标房间，以及一个后台音频任务播放器。房间之间串行执行；同一房间的点赞、弹幕和观时可按各自节奏并行推进，不要求先完成一种再开始另一种。

普通候选按用户选择的勋章等级方向排列；相同等级采用稳定顺序，避免反复刷新导致来回切换。

用户打开的直播间若符合全部资格且三项任务未完成，则优先于等级排序。进入另一个符合资格的房间时，原后台任务让出执行权；保存已确认进度及未决操作，恢复时先查询服务端，不盲目重发。

打开未授权、不满足资格或已经完成三项任务的房间，不抢占队列，也不临时获得自动互动权限。

### 5.2 三项完成与回退

当服务端最新状态确认点赞、弹幕、观时三项当日任务均完成，停止该房间的自动互动，并选择下一个符合资格且未完成的房间。

若没有其他可执行房间：

- 当前观看房间符合资格且还有任务：继续作为任务目标。
- 当前观看房间已经完成、未授权或不符合资格：释放后台任务播放器，恢复该房间的正常前台观看上报，不自动点赞或发弹幕。
- 没有正在播放的前台直播：释放后台资源，进入等待新候选状态。

正常前台观看上报仍遵守实际播放、暂停、缓冲、身份和观看记录设置；“转移回当前房间”不意味着暂停后补算或绕过房间授权。

### 5.3 前台与后台隔离

后台切房、暂停、失败或完成，不得更换前台媒体、改变画质／音量／暂停状态、跳转页面、打断聊天连接或改写手动弹幕草稿。

后台任务始终有独立生命周期。暂停或离开前台直播不停止仍符合资格的后台任务；关闭应用窗口若实际行为是最小化，则仍属于应用运行，菜单中的真正退出则停止任务。

## 6. 音频播放与观看上报

复用现有“仅播放音频”取流方式，在独立原生播放器中使用音频流。静音仅设置后台播放器的输出音量，不更改前台或系统音量，不关闭音轨或暂停解码。

以当前音频媒体就绪、播放进度持续增长、正在播放且未缓冲等真实状态驱动观看上报，不能仅用 `playing=true`、定时器运行或已获取地址证明实际播放。

同一账号的亲密度观看上报统一分配给当前任务房间；后台执行其他房间时，前台房间原有观看上报让出执行权，前台播放和聊天仍保持正常。没有任务目标或总开关关闭时，再恢复符合既有条件的正常前台观看上报。

仅音频流不可用、持续断流／解码失败、协议不支持，或经实测确认仅音频模式不能增加观时任务时，暂停该房间并显示具体原因，继续其他候选。**禁止静默或自动回退到视频。**

服务端进度可能延迟，也可能只在达到一轮门槛后更新；不能因短时间未增长就断言音频观时无效。音频结算验证应覆盖服务端任务门槛与合理结算等待，并保留明确的失败或证据不足状态。

### 6.1 实时观时与当前轮进度

在“其他设置”的后台任务状态中展示当前任务房间的观时；直播间亲密度区域展示该房间的观时，不能将后台B房间的时间显示为前台A房间的进度。

展示内容及可信度必须明确区分：

| 内容 | 依据及展示口径 |
| --- | --- |
| 官方已完成轮数 | 最新任务响应中的当日奖励轮数，例如“已完成3/10轮”；仅服务端确认后增加 |
| 官方当前轮进度 | 若服务端提供可靠的轮内已计入秒数和门槛，展示时长、剩余量及进度条，并标明最后同步状态 |
| 当前轮估算／本次有效观时 | 以当前音频实际播放、未缓冲且进度增长的时间计算，约每秒刷新；没有官方轮内数据时明确标“估算”或“本次有效观时”，不能标成官方已获得时间 |

单轮门槛从服务端可靠字段或无歧义任务文本取得，不固定写死15分钟。例如门槛确认后可显示“本轮估算05:30 / 15:00”。门槛或单位不明时显示有效观时和“进度待确认”，不填虚假百分比。

首次进入、重启或恢复时，服务端可能已保存先前的轮内时长。若无法确定当前轮起点，只展示本次有效观时与官方已完成轮数，当前轮百分比显示“待同步”；不得简单用本地累计秒数取余冒充官方轮内进度。观察到官方轮次变化并建立新的计时依据后，可以展示注明来源的估算进度。

估算计时及进度条在后台实际暂停、缓冲、断流、休眠、切房让出执行权或身份冲突时冻结；用户仅暂停前台直播、后台音频仍正常播放时继续。恢复先核对任务周期及官方轮数，只在计时依据仍有效时接续，旧本地记录不能恢复为“官方确认”。

估算达到门槛时进度条不超过100%，显示“等待官方确认”，不能自行增加完成轮数、宣布获得亲密度或触发完成转房。服务端确认新一轮后同步轮数并更新下一轮计时；三项当日全部完成仍按服务端标记判断。

上报接口已接受的秒数是另一种记录，不等同于官方结算，也不等同于全部本地有效播放秒数；可用于展开的状态说明，不作为完成凭据。实时刷新使用本地有效计时，不为每秒更新界面而每秒请求任务接口。

## 7. 完成标准、节奏与异常

### 7.1 完成标准

目标是三项任务的**当日全部完成**，不是各获得一次奖励。每轮动作数、每日奖励轮次、完成标记和任务周期均读取当前服务端数据，不写死15分钟或10轮。

例如，若服务端要求观时每15分钟一轮、每日10轮，零进度房间可能需要累计约150分钟；已累计的时间及最终结算以服务端为准。

HTTP成功、上报秒数、客户端进度、音频播放状态或本地发送预算耗尽，都不能单独标为完成。缺字段、解析失败、空任务列表或缺少观时任务也不能当作三项完成。

若当前阶段存在明确可执行的点赞／弹幕任务，但观时任务尚未出现，可以推进已知任务并重新读取阶段；仍无法确认完整任务状态时，暂停该房间并提示，继续其他候选。不得用猜测的“不适用”把房间标为完成。

任务完成缓存只用于减少重复查询。任务周期或进度发生变化后重新核对；不以设备本地零点、应用重启或清缓存直接重置发送预算。

### 7.2 互动节奏

- 自动弹幕默认随机30～60秒，每次重新选取间隔；表情模式每次从1～5个已选候选中的有效表情随机选一个，具体规则见3.3节。切房、恢复或更改内容后不立即密集补发。遵守服务端冷却、禁言和权限限制。
- 点赞采用逐次、放缓的累计节奏，拟定每次随机1～3秒；不在极短时间内一次补完几十次。若接口合并上报，数量也必须受实际累计节奏与剩余任务预算约束。
- 各项完成后立即停止该项；人工互动导致进度增加时，重新计算剩余量，避免超额。
- 自动与手动弹幕共享发送互斥和冷却，不抢占用户草稿，也不因切房形成重复提交。

随机节奏用于避免固定间隔和密集操作，**不能保证平台不会识别自动化**，也不将“避免检测”作为可宣称通过的验收结果。

### 7.3 取消、未知结果与恢复

关闭总开关／房间开关、资格失效、下播、退出登录、换号或身份转场时，取消尚未提交的操作。晚到响应不能启动旧房间、改写新账号状态或消耗新房间预算。

网络提交超时或结果未知时，保留未决记录，先只读核对服务端结果，不盲目重发。异常房间不无限占用队列；显示暂停原因，在条件恢复后重新核对再决定是否入队。

断网、缓冲、真正退出和系统休眠期间不补算观时。恢复运行时重新获取有效音频地址、任务进度和权限，处理未决记录后再执行。长期失败应有受限退避，避免频繁重试。

匿名观看、暂停记录观看或任务账号与观看账号冲突时，暂停整个后台队列并明确提示，不静默改变用户设置或替换身份。

## 8. 默认值与实施约束

| 项目 | 拟采用默认值／约束 |
| --- | --- |
| 总开关、房间授权 | 首次关闭；记住用户手动选择，账号隔离 |
| 排序 | 高等级→低等级；可切换低→高 |
| 同等级顺序 | 固定稳定顺序，建议按主播身份排序 |
| 弹幕间隔 | 30～60秒；沿用已有有效设置能力，仍遵守服务端限制 |
| 表情候选 | 每房间1～5个不同表情，每次在有效候选中等概率随机选一个；允许连续重复 |
| 观时刷新 | 本地有效观时约每秒刷新；官方轮数按任务同步更新，未知轮内起点显示待同步 |
| 点赞间隔 | 1～3秒，本轮批准的默认值 |
| 开播扫描 | 建议首版约60秒；分页、缓存和退避应限制请求频率，具体服务端限制实施前核对 |
| 后台播放器 | 每账号最多一个；仅音频、静音；无任务时释放 |
