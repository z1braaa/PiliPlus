# 直播增强与完整互动：实机验收

范围：`BUILD-LIVE-01`、`LIVE-UI-01`～`08`、`LIVE-FN-01/02`、`LIVE-TX-01`～`06`。本表是执行流程，不是已通过记录。构建号、测试日期、房间与服务端结果在实际执行后填写。默认开关为关闭；点播并发设置保持原值。

## 先验证界面与播放，不产生消费

1. 打开新包，核对“设置 → 关于”的完整版本和提交。进入“音视频”设置，首次使用或缺省配置的“直播界面增强（实验性）”应关闭。开启后退出再打开，应保留选择。
2. 选择一个正在直播的普通房间，记下画质、音量、房间号。播放中切换增强开关 20 次；画面不应重新载入，音量和画质不变，弹幕不重复。分别测试宽窗、窄窗、全屏；聊天输入时播放器快捷键不应抢走输入。
3. 打开礼物、背包、粉丝团与勋章面板。游客应明确提示登录；登录后显示当前账号、主播、库存和服务器返回的币种/价格。过期背包礼物不可发送。加载失败与空目录应能区分。
4. 选择礼物，改变数量，打开确认后按取消。核对对象、数量、单价和总额；取消后余额、背包和服务端送礼记录不变。更换账号或房间后，旧确认不可提交。
5. 暂时断开网络再恢复。记录弹幕连接状态、重试次数和恢复耗时；重试应有上限，暂停或离开后旧房间不再更新。测试中若未出现真实 SC 删除/到期，应记“真实事件未观察”，不要将夹具通过填入在线记录。

## 受控账号操作

实际发送、入团和点亮可能消耗余额或背包。测试者先自行确认当前官方价格、接收主播、数量和可接受的费用；由代理代操作时另需明确授权这些具体信息。开启开关、浏览或刷新不能触发这些动作。

| 操作 | 执行方式 | 通过口径 |
| --- | --- | --- |
| 背包发送 | 选一个未过期且可送当前房间的礼物，数量 1；确认后提交一次 | 服务端明确回执，库存按预期更新；重复点击不产生第二笔请求 |
| 金/银币礼物 | 使用当前目录中可用礼物，确认币种和总额后提交 | 服务端确认发送；明确失败显示业务原因，未知不显示成功；余额变化单独记录，不能证明未知订单成功 |
| 入团 | 进入粉丝团，读取当前入团礼物/规则；确认目标和费用后提交 | 送礼回执和当前主播的个人勋章/入团状态均核对；缺规则或权限时不能猜测一个礼物完成流程 |
| 灯牌点亮 | 读取当前灯牌状态/任务，按当前规则确认再操作 | 服务端个人灯牌状态显示点亮；佩戴图标或赠礼弹窗不能替代 |
| 佩戴/摘下 | 对已有勋章分别操作并重新读取个人勋章面板 | 佩戴和摘下状态来自服务端；不与点亮混算 |
| 结果未知 | 优先使用受控测试夹具；真实交易仅在消费上限已确认时观察自然发生的超时 | 不自动重发；原账号/房间保持绑定；只读核对无法确认则仍未知，重开面板不可解锁重复消费 |

不建议为制造超时而在实际支付过程中强制断网：可先使用确定性网络夹具验收未知结果状态机。普通礼物如果没有可靠的按订单查询协议，界面必须保留未知，由官方记录/客服核对；不要把“再次送一笔”作为恢复方式。
