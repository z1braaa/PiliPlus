# 2026-10-02 直播自动任务与观看修复

需求：`LIVE-TASK-01`、`LIVE-TASK-02`、`LIVE-WATCH-01`。用户确认默认弹幕随机间隔30～60秒，后台实际播放继续观看上报及自动弹幕。实现基线为 `0cc8dfaf8`，功能提交为 `14176e6000bbf3bebadd1d524c4a689d035febc9`，工作分支 `codex/live-task-watch`。

## 实现行为

- 直播增强互动面板的亲密度区新增两个默认关闭的独立开关、默认弹幕与随机间隔设置，按主账号保存。只对当前媒体会话运行，关闭面板不停止；后台和应用内小窗继续播放时继续执行。
- 任务读取兼容当前官方 `title/add_text/sub_title/is_done/jump_type`。明确结构化进度或无歧义的完整进度文本才提供剩余数量，奖励文本不当作目标。数量、身份或任务完成状态不明时暂停。
- 点赞先提交1次并核对进度映射，确认后每批最多5次；弹幕与手动发送共用锁，不清除手动草稿。每次提交后重读服务端任务，完成只由服务端状态确认。
- 发送前预算与未决操作写入独立Hive记录并落盘，不存凭据或弹幕正文。重进、重启与未知网络结果先只读核对；连续无进度停止发出更多互动。任务周期由服务端变化建立，本地午夜与账号代次不清空未决预算。
- 新增原生官方E/X观看会话，使用官方LIVE_BUVID、WBI及服务端滚动签名参数，按当前官方WASM输出复现原生签名。弹幕WebSocket保活和播放器本地时长不充当观看上报。
- 暂停、缓冲、媒体错误、下播或离开当前媒体会话时停止并丢弃未完成的观看区间；没有断线时间补发。延迟计时器最多上报一个完整间隔，系统冻结的真实行为未测试。
- 基础观看修复独立于增强开关。它尊重暂停历史及匿名观看设置，记录账号与主账号不一致时显示暂停原因。所有互动的UID、Cookie与CSRF显式绑定主账号；提交后未知结果不自动重试。
- 媒体房间所有权与代次隔离旧响应，自动恢复同时检查用户播放意图。接管恢复中的同一小窗由新所有者接续；暂停或下播不能由旧恢复重新启动。账号转场使用显式完成通知，失败或取消也不会永久卡住保留账号。

## 登录账号对照验收

使用同一主账号和记录观看账号、同一已开播房间，先保存官方任务目标与进度。官方网页与PiliPlus分开运行，避免重复观看会话；记录相同播放时间后服务端观看任务的增量。

开启自动点赞后核对首批对应进度以及完成后零继续提交。设置默认弹幕后开启自动弹幕，核对30～60秒随机间隔、实际发送数量和服务端完成状态；手动发送期间自动发送等待且草稿保留。任务未提供可判定数量时应显示暂停原因并保持零提交。

在前台、后台和应用内小窗分别观察播放仍在运行时的任务进度；暂停、缓冲、换房、换号、下播与关闭增强后核对待发取消。注入结果未知后重进房间或重启，确认只读核对而没有重复发送。将真实结果追加到本记录后再更新对应“已验证”状态。
