# 约束、决策与待定事项

| 编号 | 当前约定 | 依据及变更条件 |
| --- | --- | --- |
| D-01 | 点播继续使用 PiliPlus 的 Flutter / media_kit / mpv 路径；BTR 仅提供可移植的下载调度思路。 | [BTR 功能与宿主差异](../requirements/research/01-btr-updates-features.md)；若改变播放器架构，需要单独的兼容性与成本评估。 |
| D-02 | 点播多源默认按中国大陆候选组优先；不以响应速度或时延跨地区抢选。开启并发时停用旧手选 CDN。 | [已实现 V2](../parallel-cdn-playback-v2.md)和[起播需求](../requirements/02-startup-optimization-plan.md)。P2 速度加权等只作为独立可选试验，需新的明确决策。 |
| D-03 | 起播交付与稳态块大小分离，保留用户设定的并发路数和块大小。其他来源加入拼接前仍须校验资源身份。 | `NET-02`、`NET-03`、`NET-06`；工作分支已有实现和本机测试，目标网络性能门槛仍待测。 |
| D-04 | “直播界面增强（实验性）”默认关闭，与所有 CDN/直播加速开关独立；播放中可切换，不重建播放器。 | `LIVE-UI-01`～`06`；属于需求，尚未实现。 |
| D-05 | 礼物、入团、灯牌、SC 与大航海显示当前价格/权限并经用户确认；未知结果先核对，不自动重发。 | [直播路线图](../requirements/03-live-ui-roadmap.md)；实际 API、价格和回执待授权验证。 |
| D-06 | 原生 Flutter 为主布局。官方独立 H5 面板可逐模块评估嵌入，但需验证登录、桥接、导航、支付和结果回调；外部跳转不能计为应用内等量。 | [官方模块清单](../requirements/research/04-official-live-module-inventory.md)；每个模块选型待 L0 证据。 |

## 未定问题

| 问题 | 所需证据 | 下一步 |
| --- | --- | --- |
| 慢起播的主要耗时在何阶段、是否与海外缓存有关 | 目标视频/网络的地址获取、排队、首字节、校验、代理首包、首帧/音频时间线；必要时可取得的缓存响应头 | 先完成 `NET-01`；不提前固定单一根因 |
| P0 的性能门槛是否可作为发布门槛 | 同设备、同账号、同视频/画质的交替 A/B 测量和足够样本 | [验收矩阵](validation.md)中的 30% 与 500 ms 暂为目标提案 |
| 官方直播 API、H5 桥接、PC 体验 | 当前版本、账号/权限/房间矩阵及只读与授权操作记录 | L0 建立基准，随后逐模块定实现方式 |
| 直播 fMP4 HLS 网络加速 | 直播协议与目标网络的独立诊断 | 单独需求和开关，不并入界面增强 |
