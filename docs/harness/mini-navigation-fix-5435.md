# 小窗导航触发修复（5435）

日期：2026-09-30。对应 MINI-01、MINI-03、MINI-04、MINI-05。

## 用户确认与触发规则

用户截图报告：观看视频时点相关视频进入另一视频，旧视频出现小窗且无法关闭。用户本轮已明确，相关视频、播放列表、临时队列等**所有视频切换均停止旧内容，由主播放器播放新内容，整个切换不出现小窗**。

退出观看至首页、搜索、收藏等非播放页，仍沿用 MINI-01 的小窗接管规则，播放态继续、暂停态保持暂停；已有小窗后打开新媒体，沿用 MINI-05 的单会话约束。关于这两项已发出进一步问题；本轮没有将未答问题视为新的授权或新增双播放器能力。

| 操作 | 期望 |
| --- | --- |
| A 视频 → 相关/列表/队列 B | 主播放器进入 B，禁止创建 A 小窗 |
| B 视频返回 A 视频 | 主播放器返回 A，禁止创建 B 小窗 |
| 视频 → 直播/独立音频 | 交给新媒体入口，禁止旧视频小窗 |
| 已起播视频退出到非播放页 | 设置开启时出现唯一小窗；暂停态不自行播放 |
| 播放页内弹窗 | 不属于退出观看，不创建小窗 |
| 旧页面回调在新导航后到达 | 不复活旧小窗，不操作新的播放会话 |
| 关闭 A 小窗期间启动 B | 先移除 A 小窗和 A 队列游标；A 停止完成后保留 B |

## 修复

旧 `didPushNext` 对所有新页面都尝试小窗；点相关视频也是这一事件。新视频和旧页面共用全局播放器，导致旧小窗页面身份与当前媒体不一致。

新的路由观察器先记录实际导航目的页，再通知页面离开；媒体之间的 push/pop 不允许小窗。PopScope 可能先于观察器的 pop 通知，因此按原路由在栈中的下层判断；replace/remove 同样维护栈。历史 pop 的许可只在该导航代次有效，后续导航不能重新使用。

小窗关闭、还原、播放/暂停按钮绑定其显示的会话，旧按钮不能操作后来出现的小窗。关闭前清理旧队列游标，避免等待 native stop 后清除新内容；旧播放完成的异步连播也在关闭后核对导航代次，让新的用户选择优先。
