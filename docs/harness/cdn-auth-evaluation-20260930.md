## 已确认的缺陷及修改

| 确认问题 | P3 处理 | 证据边界 |
| --- | --- | --- |
| 内部等待连接名额可能被算入上游静默超时 | 获得连接名额后才启动上游等待计时；取消或旧会话退出不记为 CDN 故障 | 本地排队、单路与取消用例已通过；不代表所有网络错误都已消除 |
| 播放器缓冲满或暂停后的下游反压可能污染“CDN 低速”判断，并触发无益恢复 | 仅统计真正等待上游数据的供给窗口；输出等待不应用上游超时；恢复读取后重新积累观测 | 2 秒消费者暂停、500 毫秒上游超时的完整流用例通过；关闭和 seek 能解除等待 |
| 首包到达快不等于持续视频供给足够，较慢候选可能过早占据完整流 | 华为有效完整响应立即服务；非基线视频候选先做本次范围附近的有界小段资格测试，再开启独立完整响应 | 资格样本丢弃，不写入播放器；短样本不能证明整段、未来码率峰值或 CDN 缓存命中 |
| 资格测速与持续播放使用同一较高阈值，会把足够播放的稳定完整流拆成多个请求 | 资格暂用平均需求×2、至少 1 MiB/s；已选流持续供给暂用平均需求×1.25、至少 256 KiB/s | 本地稳定 600 KiB/s、平均需求约 342 KiB/s 用例由 24 次请求降至 4 次；这证明避免无益拆流，不证明下载越快越好 |
| 备源前部与中部验证之间响应标记发生变化，健康备源可能被反复排除 | 标记变化时最多从头重做一次完整验证；重新核对前部、中部、总量和版本 | 实际抽样发现华为响应 ETag/Last-Modified 变化，但抽样字节相同；仍严格拒绝版本、范围、总长或字节不一致的拼接 |
| 当前有序块较慢时，其他块即使先下载也不能帮助播放器继续 | 前两块缩小；阻塞块最多与一个已验证备源竞争；竞争副本纳入共享 payload 额度 | 本地顺序交付、竞争、取消和预算用例通过；竞争仍可能增加请求及流量 |
| 很短的索引或尾部请求被不必要的供给资格测试拖延 | 小范围与 suffix 请求跳过吞吐排序；未知尾部可读取 1 字节独立参考 | 仍核对 Range、长度与版本；索引字节不作免校验拼接 |

以上是实现和可控用例确认的问题。近期、低播放量、不同 CDN 响应速度和元数据变化只说明请求行为不同，**不能据此断言 CDN 未缓存视频**。没有 CDN 端缓存日志，也没有可靠的命中状态，本轮不确认“海外缓存未命中”是根因。

华为优先基线来自本轮对照的策略选择，不是恢复地理硬规则，也不表示所有华为节点永久健康。非基线资格失败和已测供给不足分别退后，错峰进入独立响应后备；初始候选选择有 6 秒总截止，但这不是整个起播必定在 6 秒内完成的承诺。

## 起播异常的独立复测

`BV13Uem6yEzo` 原默认缓冲坏轮的 1.6608 秒暂停全部发生在位置 0、加载到首次正向进度之间；真正推进后至 25 秒及 seek 后均无暂停。坏轮 file-loaded 到进度实际间隔 1.8730 秒；同组华为该间隔中位数为 0.2197 秒，额外差约 1.6533 秒，与缓存暂停吻合，支持起播 demux 供给未建立；记录缺少每轨、每来源的细时序，仍无法证明具体是视频、音频还是切源。

随后使用同一冻结核心、默认 16 秒/4 MiB，独立 S–H–H–S、30 秒进度+seek 520：4/4 完整测量。两轮并发起播为 0.8336/1.1304 秒、seek 2.2040/2.3716 秒，均无缓存暂停。华为两轮起播 2.4758/11.1128 秒，第二轮记录 3 次/12.5528 秒暂停，seek 7.2092 秒。正常供给也有时段波动；复测没有重现并发起播暂停，但不能撤销前一组的 1.6608 秒负例。

主批该坏轮缺一个 `buffered_payload_bytes` 数字字段：当时过滤器仅保留非负有界整数，原始值未保存，因此只能标记未知，既不推断负值，也不宣称所有计数归零。独立复测对 5 个原始数字分别检查类型、负值、范围及缺失，两轮并发全部有效、当次终态当前 payload/hedge/active 均为 0；这不能追溯补齐主批缺值。统计发生在桥接 close 之前，其他轮尚有资格预留或连接的快照也不能直接称为泄漏。

## 自动化验证与证据边界

[最终本地验证记录](results/cdn-auth-tests-5436.json)记载 Dart 71/71、Python 130/130、Flutter 154/154，均无失败或跳过；本轮代理、测量测试与桥接工具分析无问题。[可控传输用例记录](results/cdn-final-fixtures-5436.json)覆盖资格失败、稳定供给、小范围、暂停、关闭、seek、强校验与共享预算。

这些是不同层次的证据：可控回环测试验证实现行为，供给测试验证特定请求的字节和时序，无画面原生测试验证实际双轨解码、进度、缓存暂停和 seek。它们不能替代发行包在 PiliPlus GUI 内的首次动态画面、实际声音、交互流畅度与用户感知验收。原生“起播”是加载到正向播放进度的时间，不包含 API 取源、代理准备、所有应用界面准备和可见首帧；需与 GUI 指标分开。原生比较两模式均采用 5 秒网络超时，而应用代理缺省超时为 10 秒；限定策略与缓存行为不能当作完整应用参数逐项相同。

`observed_upstream_body_bytes` 只统计应用实际读到的响应体，不是完整线路流量；取消前未读取字节、TLS、协议与内核缓冲等不在此数中。`selected_hosts` 记录首选/初始流源，不涵盖参与的所有候选和分块。共享 64 MiB 是逻辑 payload 预留额度，不是进程总内存或播放器缓存上限。
