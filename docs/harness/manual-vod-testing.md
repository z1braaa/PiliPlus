# 点播起播与恢复：手动测试流程

更新日期：2026-09-26。测试源码基线 `17eb3762aa70a2cfc2997e134274c99ebfa615af`，安装版本 `2.1.4-CDN-P0+5409`。P0 是“优先修复起播”的开发阶段名称，不是官方发布版本号。本轮用户已确认：macOS、新加坡、有线家宽、无 VPN；运营商、设备和视频样本仍待记录。

本流程对应[追踪表](traceability.md)和[验证记录](validation.md)。2026-09-26 重新运行的代理协议 14/14、多源 15/15、起播 13/13、相关 Flutter 11/11 均通过。它们不能代替下列实机或用户网络测试。本轮不修改业务源码。

## 2. 测试准备（约 3 分钟）

1. “设置 → 关于”确认 `2.1.4-CDN-P0+5409`。只运行一个 PiliPlus 副本；每次测试都用相同入口打开，避免启动旧包。
2. 记录 macOS/设备、运营商、网络、VPN、登录状态。保持当前新加坡有线网络和无 VPN 不变；暂停其他大流量下载。
3. 应用“设置代理”的开关保持关闭。它与系统 VPN 不同，启用应用代理会绕过本轮并发传输路径。若此设置对你正常访问必需，先记录，不把开关测试当作并发功能生效。
4. 先记录并发开关/参数、手选 CDN、CDN 测速、自动播放及“空降助手”等自动跳过设置的原值，以便结束后恢复。在“设置 → 音视频设置”固定 **8 路 / 1024 KiB**；关闭 CDN 测速和自动跳过功能。不要在同一组中改参数。
5. 为比较原始地址与并发功能：关闭并发时将“CDN 设置”固定为 **基础URL（不推荐）**。这个选项仅作为原始 API 地址对照，不是日常使用推荐；测试后恢复原设置。若要比较你平常用的手选 CDN，另记为“日常配置对照”，不能与原始地址对照混算。
6. 在“播放设置”开启“自动播放”，记录原值以便测试后恢复。这样从点击进入视频到播放的时间包含地址获取。若不能使用自动播放，另记为手动播放测试，不与本组混合。
7. 选两个普通点播视频：一个你经常起播慢的视频、一个平常正常的视频；记录 BV、分 P、实际画质、编码、音轨。选开头有动态画面和预期声音的样本。保持相同账号、1 倍速、音量、解码、弹幕与字幕设置；不要使用本地文件、投屏、直播或未知非 DASH 路径。
8. 先确认实际画质/编码。每次打开的起始位置也须一致；若客户端自动续播，记录实际位置，位置不同的样本不混算。可在每轮结束前回到开头暂停，再核对下轮是否从开头进入；不要删除观看历史来“清缓存”。

## 3. 指标与计时口径

推荐用手机录到屏幕、外放声音和点击动作，事后按同一录像时间轴读数。只有秒表时，记到 0.5 秒即可，不据此判断 500 ms 的小差异。不要发送账号凭据或完整签名播放地址。

| 指标 | 起点与终点 | 注意事项 |
| --- | --- | --- |
| 首画面 Tframe | 点击进入视频 → 首个实际动态视频画面 | 封面、缩略图、加载圈不算；静态内容不适合此指标 |
| 首声音 Taudio | 同一次点击 → 首个预期声音 | 视频本身静音或晚出声时填“不适用”，不能填 0 秒 |
| 稳定起播 Tstable | 同一次点击 → 随后能连续播放至少 10 秒的区间起点 | 事后确认该区间，不能把第一次闪出画面视为稳定起播 |
| 卡顿 N / S | 连续观看 10 分钟内，非用户操作造成的 ≥0.5 秒冻结/加载次数与累计秒数 | 视频原有停顿不算；另记音频中断、最长一次卡顿 |
| seek 恢复 | 松开进度条 → 目标位置的动态画面与预期声音均恢复 | 分别记目标/实际时间戳；连续 seek 以最后一次松开为起点 |
| 重连恢复 | 已确认网络可用 → 正常画面与声音恢复 | 插回网线与网络实际就绪分别记时；无法确认就绪时，只记“插线到视频恢复”，包含系统网络恢复，不全归因于播放器。先观察自动恢复，再记录是否需手动操作 |
| 状态正确性 | 最后一次 seek/画质/音轨选择是否生效，暂停是否保留 | 错误位置、暂停被擅自恢复、持续音画不同步均单列失败 |
| 失败率 | 未成功次数 / 总尝试次数 | 60 秒是本轮观察截止，不是产品性能保证；超时记 `>60s`，不能当作成功的 60 秒 |

普通测试包的界面不能证明真实 CDN 贡献、有效/重复字节、半块续传、全部旧上游请求已取消或签名刷新成功。应用总流量也不是某视频的有效下载量。这些需后续故障注入或脱敏诊断验证。

## 4. 第一轮：快速初筛（先做慢视频，约 5～10 分钟）

测试编号 `VOD-M01`，对应 NET-01～07。

1. **关**：关闭“并发 CDN 加载”，完全退出应用，再打开应用、从相同入口进入视频并计时；看到稳定播放后继续观察约 20 秒。
2. **开**：开启并发，确认 8 路 / 1024 KiB，完全退出、重新打开并测试同视频。
3. 再按 **开 → 关** 各重复一次，共“关、开、开、关”四次。设置在下次播放/换源才生效，所以不要在同一个正在播放的源上直接切开关计时。
4. 每次填 Tframe、Taudio、Tstable、实际起始位置与任何错误。超过 60 秒未成功则记失败，退出本次，保留这个结果。
5. 再对正常视频重复四次。若任一模式反复失败，先定位，不继续扩大样本或调到 32 路。

完全退出后重开仅称为“客户端进程冷启动”，不表示清除了 CDN 服务器缓存。同一进程内立即重新进入同视频属于热启动，另作一组记录，不能混入冷启动。

## 5. 第二轮：确认起播差异与稳态收益

测试编号 `VOD-M02/03`，对应 NET-01～07。

- 有可复现差异后，每视频每模式至少 5 次。十次顺序：**关、开、开、关、开、关、关、开、关、开**。保留全部单次数据，以中位数、最小/最大值和失败率初筛；不把失败删掉后声称整体成功。
- 起播测试不必每次观看 10 分钟。另对慢视频“关/开”各看 10 分钟，记录卡顿次数、总时长和最长卡顿；必要时按相反顺序再做一组。正常视频也有明显退化时，单独复核。
- 当前包内关闭/开启回答“这个功能在你的网络上有没有净收益”。文档的 **30% 候选目标是 V2 开启与 P0 开启的比较**；要验证它，还需用相同参数和样本交替测试两版，并每次核对关于页版本。两版还合入了不同上游提交，应保留这一限制。
- 每组 5 次不是 P95 验收。健康样本“额外 P95 ≤500 ms”也不能用秒表和少量样本判定。正式验收另定样本量、录制精度和波动处理；本轮先看明显退化与重复失败。

## 6. 第三轮：恢复与状态正确性（约 10～20 分钟）

先在并发开启 8 路 / 1024 KiB 下执行；发现异常后在关闭模式重复同一步，以区分既有播放器问题与新路径问题。测试前确认原位置/状态，观察截止均为 60 秒并记录实际耗时，不预设恢复速度已达标。

| 编号 / 对应需求 | 操作 | 记录与判定 |
| --- | --- | --- |
| VOD-M04 / NET-04/11 | 稳定播放后向后跳约 15 秒；再跳到远处（例如全片 70%） | 目标与实际位置、恢复时间、声音；近距离和远距离分别记录。只有缓冲范围实际可见时才标“缓冲外”，否则不能宣称覆盖了该路径 |
| VOD-M05 / NET-11 | 约 1 秒间隔依次跳到全片 20% → 70% → 40% | 最后 40% 生效；没有被旧结果拉回 20%/70%，没有异常自动暂停 |
| VOD-M06 / NET-11 | 播放中切一次画质；暂停后再切一次；有多音轨时同样检查 | 最终画质/音轨正确；暂停场景继续暂停，不擅自出声。没有可选音轨填“不适用” |
| VOD-M07 / NET-09/10/11 | 暂停 5 分钟再恢复；疑似长暂停故障可另测 30 分钟 | 位置、恢复、错误文字与手动操作。暂停时长不等于签名已过期；成功也不证明刷新了地址 |
| VOD-M08 / NET-08/09/11 | 播放稳定后短暂断开有线网络 10～30 秒；看到缓冲耗尽再恢复网络 | 先等自动恢复，不立即点播放；记录断网是否真的造成卡顿、插线/确认联网/视频恢复时间和手动操作。如果一直播放，记“未触发恢复”，不是通过 |
| VOD-M09 / NET-07/11 | 加载或恢复期间退出该视频，打开另一个视频；可复查窗口关闭/睡眠唤醒 | 新视频和最后选择生效，旧视频不突然发声/覆盖状态；界面正常不等于旧网络任务完全取消 |

操作断网只在你方便中断当前电脑连接时执行；不要改路由器或影响其他设备。若应用离线但系统仍有别的连接，记录实际网络状态。本轮手工不能可靠制造 403/429、部分块断线或签名到期，这些留给受控测试。

## 7. 参数边界：有问题时再测

基线完成后，功能均开启，分两组做参数对照：第一组 A=8 路 / 1024 KiB，B=2 路 / 1024 KiB；第二组 A=8 路 / 1024 KiB，B=8 路 / 4096 KiB。每组先 A → B → B → A 四次，仍用同一实际画质、编码与位置。每组只改变一个参数，不能同时改路数和块大小后归因。

1 路可作为串行边界观察，但已有音频等待限制，不属于 ≥2 路的保证范围。32 路、内存与重复流量验收优先用受控监测，不要求用户先做全组合测试。
